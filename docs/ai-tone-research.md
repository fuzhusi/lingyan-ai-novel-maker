# 降 AI 率方案调研报告

> 背景：生成的小说在腾讯朱雀（AA 检测）判定 AI 率约 80%。目标：让生成文本的写作特征向人类作者收敛。
> 本报告汇总朱雀检测原理分析、三个开源方案逆向、以及一份 283 万字对照语料研究的结论，并给出落地方案。
> 日期：2026-08-25

---

## 一、朱雀检测原理

腾讯混元安全团队开发，140 万正负样本训练，中文检出率 >92%，每日更新训练数据（持续进化的对抗系统）。

| 维度 | 检测内容 | AI 典型表现 |
|------|---------|------------|
| 困惑度 Perplexity | 用词可预测性 | 选词永远是最优解，"太顺了" |
| 突发性 Burstiness | 句长/句式波动 | 句长标准差小，等长句连排 |
| 语义连贯性 | 段间过渡 | 过渡丝滑、逻辑链完美无跳跃 |
| 词汇分布指纹 | n-gram / 各模型偏好词库 | 高频命中套话体系 |
| 跨段一致性 | 各段风格均匀度 | 全文风格统一无自然波动 |

关键认知：

1. **朱雀是"写作风格分析器"，不是查重**。它检测"写作模式是否像 AI"，不是内容来源。换词无效，要换"统计指纹"。
2. **AI 率是整体概率判断**（60% AI 率 = 这篇文章有六成概率整体由 AI 生成），不是"60% 的字是 AI 写的"。
3. **支持段落级定位**——未修改到位的段落会被单独标红。整体稀释无效，必须逐段过关。
4. 无公开 API，网页端有验证码反爬；检测标准持续演进，今天能过检的内容明天可能过不了。

## 二、现有体系的结构性缺陷（代码审查结论）

| # | 缺陷 | 说明 |
|---|------|------|
| 1 | 只做删减不做重构 | `deai_process` 是字符串手术（删词/替换/剥引导壳），对困惑度分布影响有限 |
| 2 | 零量化指标 | 无句长方差、连接词密度、n-gram 重复率计算；无法回答"这篇比上一篇人味高多少" |
| 3 | 没有反馈闭环 | skill_gate 只报告不阻断不修订，靠用户手改 |
| 4 | 注意力稀释 | 去AI约束约 4400 字占 system 开头，user message 上下文动辄数千字，约束权重被稀释 |
| 5 | 流式路径裸奔 | SSE 生成不经检查，续写补足拼接文本无节奏平滑 |
| 6 | 对抗面单一 | 只针对词汇层套话，对篇章层特征（段首回指/相邻句同构/冒号破折号）零覆盖 |
| 7 | 存在反向规则 | 比喻简化规则删除的恰是人类写作标志特征（见 §四），越删越像 AI |

## 三、开源方案调研

### 3.1 swaylq/humanize-chinese（211★）

两代架构对比本身就是答案：

- **v5（已弃用）**：同义词林替换 + 噪声注入 + 追分数 → 作者用通顺度评审团证伪（产物中位 2.0/5 分）。**证明纯规则替换路线是死路。**
- **v6（现行）**：LLM 带人味直接写 → 守卫+评审团闭环定点改写 → 纯标点节奏修复。

HC3 校准统计特征表（供参考，未经小说体裁对照验证）：

| 特征 | 人类 vs AI | Cohen's d |
|------|-----------|-----------|
| 句长变异系数 CV | 0.52 vs 0.32 | 1.22 |
| 短句占比(<10字) | 25% vs 2.6% | 1.21 |
| 段内句长 CV 均值 | 0.485 vs 0.288 | -2.08（长文最强） |
| 段落长度 CV | 0.742 vs 0.359 | -1.49 |
| 跨段 trigram 重复率 | 0.018 vs 0.064 | +1.13 |

教训：强相关指标简单加权堆叠会饱和失效——要么只用互不重叠的少数几个，要么攒样本训逻辑回归。

**关键实证**：LLM 直接"带着人味写"句长 CV 可达 0.62，事后改写只能到 0.31 → 重心必须在写作时。

### 3.2 qoqu/anti-zhuque（直接针对朱雀）

六维诊断：burstiness（含均匀三连句检测）、过渡词密度、AI 高频词、否定式排比/三段式正则、句式重复率、跨段一致性。含专门 `NOVEL_AI_WORDS` 词库。工作流 = 诊断→生成针对性改写 prompt→复验。

### 3.3 lynote-ai/humanize-text（翻译链）

多引擎翻译跳转打散统计特征。**不采用**——摧毁文风与上下文一致性，与长篇一致性体系冲突。

### 3.4 larashero3-dotcom/lieflat-less-ai-tone（128★，方法论最硬）

283 万字对照语料研究：300 篇由 5 个主流模型受控生成 vs 329 篇人类文本，对 26 项流传的"AI 文风"特征逐项做频率比检验（R = 生成÷人类，R≥2 才纳入），附六次测量失误复盘。

#### 通过检验的 11 项特征

| # | 特征 | R | 改法要点 |
|---|------|---|---------|
| 11 | 段首零回指评论 | **4.4** | 补一个回指词（多为"这"字）即可 |
| 7 | 拟人化喻体（"像一位智慧的导师"） | 7.3 | 换成实际做了什么，或具体的人作喻体 |
| 5 | 冒号滥用（提示语冒号 3.8 / 空转列表冒号 9.4） | 3.8/9.4 | 删提示语或换标点 |
| 10 | 译文句式五种（过长前置定语 / 当…时 / 对于…来说 / 句首连接词 / "这意味着"复述） | 2.6–5.3 | 拆句/去壳/移位 |
| 1 | 翻案腔（不是A而是B 全家族："看似…实则""你以为…其实""说到底"…） | 3.4 | 直接正面下判断 |
| 4 | 破折号揭晓式用法（DeepSeek 5.16‰，人类 0.80‰） | 3.0 | 改逗号/句号或写完整句 |
| 9 | 起首语（说白了/说穿了/先说结论） | 3.2 | 删掉直接给判断 |
| 3 | 相邻句结构同款（逗号数/成分序相同连排） | 2.0 | 打散其中一句句法 |
| 6 | 序数词当小标题 | 3.1 | 小说场景不适用 |
| 2 | 顿号并列过密（一句内 ≥2 顿号串三项以上） | 1.8 | 概括或改一项句法 |
| 8 | 概括表述覆盖已有数据 | 反向 0.35 | 恢复动词，不许编数据 |

#### 未通过检验的 15 项（方向相反者标 ⚠）

| 特征 | R | 结论 |
|------|---|------|
| ⚠ 比喻 | 0.42 | **人类是 AI 的 2.4 倍**，比喻独立成段 8 倍。差异只在喻体选择（AI 偏好理想化职业人格） |
| ⚠ 正文设问 | 0.05 | **人类是 AI 的 17 倍**。按流行建议删设问会更像 AI |
| ⚠ 句内同构排比 | 0.61 | 人类更高。只有跨相邻句的同构才成立（R=2.0） |
| 句长均匀度 | 0.87 | 实测无差异（初测"51倍"系分句程序缺陷） |
| 相邻句长差 | 1.00 | 无差异 |
| 单字虚词「就」偏少 | 0.45 | 方向是补不是删，且补虚词无法验收，弃用 |
| 设问自答 | 1.03 | 无差异 |
| 抽象被动/名词化/"使得…能够"/"扮演…角色"/"以一种…的方式" | <0.1 | 现代汉语已吸纳，非区别性特征 |

#### 方法学礼物（比规则更值钱）

1. **白名单原则 + 信息守恒**：只处理清单内规则；未命中句子逐字保留；改写后每个实词须能在原文指出出处；不得抹掉限定词（"可能"→"提升"是篡改判断强度）
2. **算子抽样检视规程**：任何新正则采信前先人工检视 20 条命中实例（其六次失误中四次会入规则集、两次方向相反）
3. **分母选择纪律**：按特征依附的语言单位选分母（每千字/每百段/占比）
4. **风格优先**：目标作者的真实习惯不算 AI 痕迹，风格文档与去AI规则冲突时以风格文档为准
5. **模型个体差异**：同一特征极差可达 40 倍（破折号 DeepSeek 5.16 vs GPT 0.11）。我们 writer 默认 DeepSeek → 破折号/提示性冒号是必查项

## 四、对我们系统的核心冲击

1. **`_fix_sentence_structure` 的 8 条比喻简化规则在帮倒忙**——删除的是人类 2.4 倍密度的标志特征 → Phase 0 下线
2. **skill_gate 三连排比需区分句内/跨句**——句内排比不能扣分，仅跨相邻句同构成立
3. **词汇层规则已够甚至过量，篇章层接近空白**——段首零回指(R=4.4)、冒号滥用(9.4)、破折号(DeepSeek 高发)全部无覆盖
4. **统计节奏类特征存在证据冲突**（humanize-chinese 说最强信号，lieflat 说无差异），必须在我们自己的小说语料上测量后再纳入评分

## 五、落地方案

| 阶段 | 内容 | 状态 |
|------|------|------|
| **Phase 0 止血** | 下线比喻简化规则；gate 排比改为仅跨句同构；修复损坏的 few-shot 示例 | ✅ 已完成 |
| **Phase 1a 确定性检测** | 新建 `ai_metric.py`：11 条已验证特征的确定性检测 + 统计指标（信息性展示，暂不计分），接入 gate-check API 与前端 | ✅ 已完成 |
| **Phase 1b 自建语料校准** | 用朱雀标红的稿件做正样本，测量统计特征在我们的小说体裁上是否有区分力，有则纳入评分 | 待朱雀测试数据 |
| Phase 2 标点节奏 pass | ~~纯标点断句调节奏~~ | ⏸ 降级待验证（证据冲突） |
| Phase 3 定向修复闭环 | ~~gate+metric 违规条目带摘录回喂定向修复调用~~ → **已实现「指纹注入」形态**：`build_tone_instructions()` 把检测违规转为修正指令，自动注入三条生成链路（长篇章节生成 / 短篇逐节点生成 / 评审重写），二次生成时模型主动避开已形成的构式指纹；人名类三元组经功能字过滤自动排除 | ✅ 已完成 |
| Phase 4 写作侧纠偏 | 约束瘦身+首尾锚定；加入负面清单（别删设问/比喻/句内排比）；DeepSeek 破折号/冒号专项约束 | ✅ 第一批已完成 |

## 六、验收与迭代方式

1. 每次生成后跑 `/api/skills/gate-check` 查看 ai_tone 报告（11 项命中明细 + 统计指标）
2. 用户将生成稿提交朱雀检测，回填 AI 率到本文档下方记录表
3. 攒够样本后校准内部评分与朱雀分数的相关性，决定是否训轻量 LR 对齐

### 朱雀测试记录表

| 日期 | 稿件 | 处理管线 | 内部人味分 | 朱雀 AI 率 | 结论 |
|------|------|---------|-----------|-----------|------|
| 2026-08-25 | 无题短篇 #2（9610 字，5 节点生成） | Phase 0+4（约束纠偏+比喻规则停用） | 100（旧版 9 项） | **44%**（疑似率 45%） | 首个校准点：词汇层全净仍被标红 → 病灶在篇章统计层。画像分析定位两处：跨段三元组重复率 0.0977（AI 均值 0.064 的 1.5 倍）、相邻句结构同款 21.7/百段（AI 参考 9.4）。两项已纳入计分（跨段重复 w=18 / 结构同款密度化 w=12），该稿新评分 70 分 |
| 2026-08-25 | 新无题短篇 + 指纹注入二次重写 | Phase 3 指纹注入闭环 | 74 | **6.61%**（疑似 91.87% / 真人率仅 1.52%） | 三桶概率模型确认（三数和=100）。指纹注入把「确定AI」桶打掉了，但文本落入「不确定」桶——既无AI特征也无人类特征。诊断：规则堆叠把文本雕刻成"第三种文体"；且朱雀 2026-03 升级专门识别短句AI模式，我们的短碎句 few-shot 方向反了 |

**校准结论**：
- 内部人味分与朱雀判定的相关性依赖篇章层信号——仅靠词汇层干净可从 80% 降到 44%，但压不进低区间
- 跨段措辞重复是逐节点生成的结构性病灶（各节点独立产出相同构式），规则替换无法根治，需要 Phase 3 定向改写或节点提示词多样化
- 句长 CV 0.587、短句占比 30% 已达人类区间，证明节奏侧改造有效，无需 Phase 2 标点节奏 pass
- **44%→6.61% 的跃迁证明指令闭环有效；但「疑似桶」需要正向人类特征（材料密度/情绪表达/不完美感），规则禁令产生不了正向特征——策略从「禁止什么」转向「注入什么」**

## 七、方向修正（2026-08-25 第二轮调研）

前人案例调研核心发现：

1. **朱雀 2026-03 升级重点识别短句 AI 模式**——「优先15字短句」「碎片句」的导向已被针对性建档，须纠偏
2. **墨云实验（100%→0%）**：有效手段全是正面指令——①注入情绪表达（"价格较高"→"贵死了"）②拥抱不完美（话说一半、跑题、自我打断）③制造不确定性
3. **InkOS 先例**：style_profile.json 文风锚定注入 + spot-fix 定点修复——验证我们架构方向
4. **采样参数参考值**：创意写作 temperature 0.9 + presence 0.8 + frequency 0.9，重复词率 15-20%→2-5%
5. **平台现实**：番茄/起点要求人工改写占比 ≥30%；「AI搭骨架、血肉必须是人的」是行业共识——全自动压真人率有天花板

**新策略组合（不再堆约束词）**：

| 手段 | 落地 | 状态 |
|------|------|------|
| A. 风格锚定 | 用户提供真人文本 → style_fingerprint 存储 → 全链路注入（长篇已有，短篇节点/重写已接入） | 基建完成，待用户锚例文本 |
| B. 采样层干预 | frequency_penalty/presence_penalty per-agent 配置（CLI `agent-param` + Web 设置页采样惩罚列）；已设 writer/short_story = 0.5/0.5 | ✅ 已完成 |
| C. 提示词人工重写 | 用户亲自重写 `DEFAULT_WRITER_CONSTRAINTS`（app/services/prompt_builder/context.py）——纠偏短碎句导向，注入情绪化表达与不完美感 | 由用户执行 |
| D. 段落级人机协作 | 前端 diff 建议采纳（长期方向） | 未启动 |
