# GitHub 同类项目对照（2026-09-06）

## 对照范围

| 项目 | 参考点 | 结论 |
|---|---|---|
| [chinese-novelist-skill](https://github.com/PenglongHuang/chinese-novelist-skill) | 三层引导问答、偏好记忆、中断续写、字数校验、自动重写 | 灵砚已有偏好档案、断点续跑、字数下限续写与超标压缩；本次不重复搬流程，保留其“校验失败不越过闸门”的思想 |
| [OpenFic](https://github.com/syrizelink/OpenFic) | CI/发布工程、结构化项目数据、跨端交付、Agentic RAG | 灵砚已有 SQLite 真源、FTS5 检索与 Web 单机定位；本次采纳 CI，暂不引入桌面壳、向量库或发布自动化 |

## 本次吸收

1. **质量闸门收紧**：一键本章在收敛后对最终稿复测技能门禁与 AI 痕迹；未通过时返回终稿与失败原因，停在人工审阅前，`auto_save` 不落库。
2. **前端语法修复**：写作页三处提示文案改为转义换行，避免整段脚本解析失败。
3. **持续集成**：新增 GitHub Actions，在 Python 3.14 + uv 环境安装依赖并运行完整测试。

## 明确不吸收

- 不把“全自动整本生成”作为默认路线：与灵砚“人工主导”的产品红线冲突。
- 不为了 RAG 引入新数据库：现有 FTS5 与分层摘要是当前架构的低依赖优势。
- 不同时引入桌面壳与容器发布：先让测试和发布质量稳定，再考虑分发形态。
