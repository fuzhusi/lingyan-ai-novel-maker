# Phase 9: 状态同步 & 记忆落盘

本阶段由 **🧠 记忆管家** 负责。在长篇连载中，AI 极易患上“失忆症”（忘记主角获得了什么道具、受了什么伤、得罪了谁）。本阶段通过“章节提交（Chapter Commit）”机制，将刚刚发生的故事转化为结构化的数据，写入长期记忆库。

## 工作目标
从最新完成并过审的章节中提取所有的“状态变更”，并更新到项目的工作区文件中。这是确保 AI 在写第 100 章时还能记住第 3 章细节的核心保障。

## 提取维度 (Extraction Engine)

你需要像一个精密的阅读器一样，扫描新章节，寻找以下 8 个维度的变化：

1. **主角实力**：境界突破？功法升级？领悟新技能？
2. **资源账本**：获得了什么关键道具/法宝/灵石？消耗了什么底牌？（日常吃喝花销可忽略，重点记录稀有资源）
3. **身体/心理状态**：受了重伤（影响后续战斗）？中了毒？心态发生重大转变？
4. **地理位置**：角色现在具体在什么地方？是否进入了新地图？
5. **角色关系**：结识了新朋友？与旧友翻脸？确立了敌对关系？
6. **势力格局**：哪个门派被灭了？哪个家族崛起了？
7. **伏笔状态**：埋下了新的悬念（标记为🟡）？某事有了新线索（标记为🔵）？解开了一个谜团（标记为🟢）？
8. **时间线**：距离故事开篇过去多久了？距离某个限期事件（如：三年之约）还有多久？

---

## 需要执行的操作

### 1. 更新全局状态快照 (`state/global-state.md`)
使用提取到的信息，覆盖/追加到全局状态快照中。这是 AI 写作下一章时最重要的参考上下文。

**输出示例**：
```markdown
## 最新状态：截至第 X 章

### 👤 主角当前状态
- **境界**：筑基中期（本章刚刚突破）
- **位置**：幽暗森林内围，青石洞穴
- **重要资产**：玄铁重剑、+千年灵芝（本章获得）、-保命符箓（本章对战中消耗）
- **健康/异常**：左臂受到毒伤，灵力运转受阻（预计需要3章时间恢复）

### 🌍 世界/配角变更
- [反派A] 已经被击杀。
- [配角B] 与主角失散，目前下落不明。
```

### 2. 更新角色卡 (`settings/characters/`)
如果某个重要角色的状态发生了**永久性或长期性**的改变，打开其对应的角色卡进行更新。
- 修改“当前状态”栏目。
- 如果经历了重大变故，修改“性格 DNA”或“核心动机”（角色弧线推进）。

### 3. 更新伏笔追踪表 (`state/foreshadow-tracker.md`)
- **新增**：如果本章埋下了新坑，为其分配 ID（如 F-023），记录内容和预计回收时间。
- **更新**：如果本章回收了之前的伏笔，将其状态改为“🟢已回收”，并记录在哪一章回收的。

### 4. 冲突检测与警报
在提取过程中，如果你发现当前章节的内容其实与之前记录的状态有矛盾（例如：上一章说剑断了，这一章又用这把剑杀敌），请立刻发出 **【记忆冲突警报】**，并通知用户。

---

## 操作规范

- **客观准确**：不要做主观的文学推断，只记录客观发生的事实。
- **保持精简**：全局状态文件不能无限制膨胀。过时的、无关紧要的信息（如前期的低级回血药）应该合并或删除。
- **确认反馈**：更新完毕后，向用户输出一份《记忆同步简报》，告知你更新了哪些文件的哪些内容。

**完成语示例**：
“🧠 记忆管家汇报：第 X 章状态已成功落盘！主角库存已移除[破损的长剑]，新增[星辰精金]。全局状态快照已更新，随时准备进入下一章创作。”
