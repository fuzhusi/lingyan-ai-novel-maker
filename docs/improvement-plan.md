## 二、整改原则

### 原则 1：用户优先
所有改进以用户体验为核心，先解决最影响用户的问题。

### 原则 2：渐进式改进
分阶段实施，每阶段可独立交付，避免大爆炸式改动。

### 原则 3：保持技术优势
在改进体验的同时，不得削弱 Per-Agent 模型配置等核心优势。

### 原则 4：数据驱动
关键改进前收集用户反馈，改进后用数据验证效果。

## 三、问题分级与整改任务

### 🔴 P0 - 严重问题（必须解决）

#### P0-1: 缺少新手引导
- **当前问题：** 首页无任何引导，新用户不知道从何开始
- **影响范围：** 70% 新用户 30 秒内流失
- **验收标准：**
  - [ ] 首页添加「快速开始」按钮（1 步点击进入示例）
  - [ ] 首次访问显示引导悬浮窗
  - [ ] 至少 3 个示例小说（玄幻/科幻/言情）
  - [ ] 每个示例含完整角色、世界观、5 章节大纲
- **工作量：** 2-3 天
- **优先级：** 🔴 最高

#### P0-2: UI 视觉粗糙
- **当前问题：** "Ink & Shadow" 主题缺乏视觉层次和细节
- **影响范围：** 用户第一印象，专业感不足
- **验收标准：**
  - [ ] 首页重新设计，含 hero section 和特性卡片
  - [ ] 字体层级优化（标题/正文/辅助文字）
  - [ ] 颜色搭配优化，提升对比度
  - [ ] 添加动画过渡（hover/focus 状态）
  - [ ] 卡片阴影和圆角统一
- **工作量：** 5-7 天
- **优先级：** 🔴 最高

#### P0-3: 无用户认证
- **当前问题：** `/novel/1/delete` 等接口无鉴权
- **影响范围：** 任何人都能修改/删除数据
- **验收标准：**
  - [ ] 添加登录页 `/login`
  - [ ] Session-based 认证
  - [ ] 全局 `before_request` 鉴权钩子
  - [ ] 注销功能
  - [ ] 至少一个默认账号
- **工作量：** 1-2 天
- **优先级：** 🔴 高

### 🟡 P1 - 重要问题

#### P1-1: 评审按钮发现性差
- **当前问题：** 用户反馈评审按钮看不到（已修复，需进一步优化）
- **影响范围：** 短篇质量控制能力
- **验收标准：**
  - [ ] 评审按钮始终可见，无内容时显示禁用状态
  - [ ] 评审按钮添加图标和更醒目标签
  - [ ] 添加使用说明 tooltip
- **工作量：** 0.5 天
- **优先级：** 🟡 高
- **状态：** 部分完成 ✅

#### P1-2: 缺少使用统计
- **当前问题：** 没有"今日生成 X 字"、"累计 X 章"等激励指标
- **影响范围：** 长期留存率低
- **验收标准：**
  - [ ] Dashboard 添加个人统计卡片
  - [ ] 字数、章节、灵感计数
  - [ ] 连续创作天数（streak）
  - [ ] 周/月图表
- **工作量：** 2-3 天
- **优先级：** 🟡 中

#### P1-3: 流式生成无保存提示
- **当前问题：** 生成过程中意外刷新页面会丢失内容
- **影响范围：** 用户数据安全
- **验收标准：**
  - [ ] 自动每 10 秒保存草稿到 localStorage
  - [ ] 页面刷新时检测并恢复草稿
  - [ ] 草稿与服务器内容对比，提供选择
- **工作量：** 1-2 天
- **优先级：** 🟡 中

#### P1-4: 角色管理繁琐
- **当前问题：** 创建角色需要填写 7 个字段
- **影响范围：** 用户入门成本
- **验收标准：**
  - [ ] 角色创建页改为分步表单（基础/性格/背景/弧光）
  - [ ] 提供"AI 自动生成角色"功能
  - [ ] 角色模板库（10+ 预设角色）
- **工作量：** 3-5 天
- **优先级：** 🟡 中

### 🟢 P2 - 体验优化

#### P2-1: 章节大纲输入门槛高
- **验收标准：**

#### P2-4: 设置页 Per-Agent 配置引导

  - [ ] 配置页面增加新手教程链接
  - [ ] 配置生效提示
- **工作量：** 1 天

#### P2-5: 仪表盘功能扩展

## 七、风险评估

### ⚠️ 主要风险

| 风险 | 可能性 | 影响 | 应对方案 |
|------|--------|------|---------|
| UI 改版影响现有用户 | 中 | 中 | 保留旧版入口，A/B 测试 |
| 用户认证引入兼容性问题 | 低 | 中 | 先做内测，充分验证 |
| 移动端开发延期 | 中 | 低 | 优先级调整，先做核心页 |
| AI 模型成本增加 | 中 | 高 | 监控 token 用量，按需优化 |

### 🛡️ 风险缓解

1. **每个阶段独立发布**，可随时回滚
2. **保留旧 API 兼容**，至少 6 个月
3. **建立用户反馈群**，及时收集意见
4. **每周进度评审**，及时调整方向
