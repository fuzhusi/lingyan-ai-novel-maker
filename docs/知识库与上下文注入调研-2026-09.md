# 知识库统一与上下文注入：评审后实施计划（v2，2026-09-30）

> v1 讨论稿经三路评审（架构审评 / 前端信息架构审评 / 红队反方）后修订。
> 评审结论：方向成立，v1 有三处硬伤假设被推翻，第一步范围收窄，前端提案采纳修正版（大纲不进知识库）。

---

## 〇、评审推翻的三处硬伤（对 v1 的修正）

1. **temporal_truth 不是表**——它是 Setting 表里按书一个 JSON 键，且 `add_truth/update_truth` 已有 `to_chapter` 闭合逻辑（bi-temporal 已半成型）。v1 说"加 invalid_chapter 列迁移"前提错误，实际只需 JSON 结构演进。
2. **"默认 semantic = 等价现状"不成立**——实测 data.db 中 `entity_embeddings` 为 0 行，语义过滤从未真正生效过；实际在裁角色的是大纲名册过滤。默认 policy 若设 semantic 反而是行为变更，破坏兼容红线。**默认模式必须叫 auto（名册过滤+全量兜底，精确复刻现状），semantic 是嵌入管道建成后的 opt-in。**
3. **"稳定前缀区/压缩只对知识区"与现状错位**——罗盘在 user 块、文风锚例混在 memory_context 尾部、style_memo 逐章变，前缀字节今天就不稳定；apply_context_budget 压的是 summaries/world/characters 等五个 kw 字段。分区装配是重构不是搬运，压缩的"砍次要字段"语义必须迁成 character provider 的 compact 渲染档。

另：注入管道实数 **17 处** try/except（v1 写 14+）；大纲树**没有**拖拽（排序是创建序）。

## 一、决策一（注入架构）：采纳红队让步版——观测层先行，收拢降级

**路线**：观测层 → 三源 provider 化（兼容渲染）→ 尾部复述区 → 数据驱动的后续收拢。**不做** ST 式字段矩阵、不做 policy UI、大纲/伏笔页保持独立。

### 第 0 步：观测层（~1 天，最高性价比）
- 新服务注入清单记录器：build_writer_kwargs 的 17 处管道每处登记 `{维度, 激活/降级/跳过, 字符数, 原因}`
- 透传两端：SSE status 帧（进度行可见）+ 章节版本 model_params_json 旁的注入报告
- 收益：静默失效变可见失效（writer_chain.py:305 的历史事故模式永久闭环）；为后续一切收拢提供数据

### 第 1 步：三源 provider 化（~3 天）
- world/character/memory 三源收拢为 provider（统一接口：candidates → 激活 → compact/full 渲染档），**兼容输出现有 kw 字段**——拍路径 `_beat_context_block` 零改动
- 顺序约束显式化（架构审评红线）：名册过滤 → 语义/keywords 激活 → 统一压缩 → 豁免区渲染；provider 只产候选，不直接写 kw
- policy 字段最小集落地：`injection_policy` JSON 列加到 characters/world_settings（MIGRATIONS 追加 2 条）；默认值 `{"mode": "auto"}` 精确复刻现状；**拆书落库条目默认 keywords**（防全 auto 退化全量）
- 无 policy UI——调 policy 走 JSON（作者可选）
- 前置项：entity_embeddings 建嵌入管道（蓝图采纳后建向量已有半截，补全后 semantic 才是活的）

### 第 2 步：尾部复述区 + 排序修正（~1 天）
- 罗盘一句话复述 + 章尾钩复述进 prompt 尾部（lost-in-the-middle 对策）
- 近章细节移尾部吃近因效应；检索记忆最强条目置首尾
- 预算分区比例（30/25/30/5/10）写为常量，实跑定标

### 第 3 步（数据驱动，暂缓）：bi-temporal JSON 演进、实体邻域检索（HippoRAG 种子扩散）、policy UI、递归激活、cooldown/delay——触发条件：观测层数据显示某类注入系统性失效，或作者实际开始调 policy

### 明确不做
- LLMLingua 整体替换（删虚词伤文风+毁前缀缓存）；全局情绪弧线分类；ST 字段矩阵全量

## 二、决策二（前端信息架构）：采纳修正版——部分合并，大纲不进

**采纳用户提案的核心**：人物/世界观/伏笔合并为侧边栏单一「知识库」模块（`/knowledge` 容器 + Tab），新增知识类型（记忆/读者已知/偏好）直接加 Tab。
**部分否决**：大纲树**不进**知识库——它是"动词"页（结构工作台：与 chapter 表双向同步、写作页 1476 行内联回写、AI 摘要反拉知识库），塞进 Tab 会迫使知识库为写作联动买单回归。伏笔页保留排程工具属性，作为知识库 Tab 时排程操作保持原 API。

**实施要点**（3-4 人日）：
- `/knowledge?tab=characters|world|foreshadowing` 容器页复用现有模板片段（三页结构同构：card-list+隐藏编辑表单）
- 旧 URL 301 别名保留深链；表单 action 改一次
- 6 个模板重复维护的书内 nav 块收敛为一个 include（顺手清债）
- 大纲保持独立入口，知识库页加大纲快捷卡

## 三、实施顺序

1. 观测层（第 0 步）——独立可上线，立即生效
2. 前端知识库模块（方案 B）——与 0 并行，纯前端
3. 三源 provider 化 + policy 最小集（第 1 步）
4. 尾部复述区 + 排序修正（第 2 步）
5. 书 1 第 26 章实跑验收（门禁报告+注入报告+盲审对照）→ 数据决定第 3 步是否启动
