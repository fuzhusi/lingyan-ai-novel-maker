# 跨章冲突生命周期：四专家方案合并裁决（v1 定稿，2026-10-03）

> 流程：叙事结构师 / 网文主编 / 架构师 / 红队四路独立提案 → 本文档合并裁决。
> 裁决原则：红队的代码事实为锚（防止装饰性字段），主编的工业经验定方向（欠账而非结清），架构师定承载（新表 vs 复用），叙事师定语义（遗留 vs 钩子 vs 伏笔的边界）。

---

## 一、概念定名与边界（采纳叙事师框架，全队无异议）

- **钩子 = 读者视角**（下一章为什么读；可以是悬念/情绪）——已有【结尾钩子】字段承载
- **遗留冲突（open loop）= 故事视角**（主角世界里哪笔账未清；双方知情、进行中的对抗/义务）
- **伏笔 = 秘密**（信息不对称）——已有 Foreshadowing 账本承载
- **判别测试**：能复述为「X 欠 Y 一场对峙/一个交代」= 遗留；需要「其实…」才成立 = 伏笔（转账本）
- **关系**：遗留是账户，钩子是当前帧——好章尾 = 遗留最新一次升级被写成钩子

## 二、裁决结果：红队砍掉三样、保留三样的收窄版，吸收主编与叙事师各一 enhancement

### 砍掉（红队成立）
1. ❌ 细纲第 8 字段【遗留冲突】：写前无真值、GLM 会填「无」或万能句（chapter_events 800 tokens 撑爆实测 + upgrade prompt「没有写无」先例），软通过拦不住装饰填法。**改在成文后采集**（真值在正文里）。
2. ❌ 钩子正文呼应检测：名词重复假阳性 + 后果句假阴性专杀好写法（gate 注释史即误报史）。**只比【结尾钩子】字段 vs 下章细纲文本**，且仅诊断不阻断。
3. ❌ LLM 判 resolved：resolved 是终态，判错即真冲突无人管（must_payoff 可靠恰因永不采信 LLM 的 resolved）。**LLM 只能提案，resolved 仅人工或确定性确认**。

### 保留 + 合并 enhancement
1. ✅ **open_loops 新表**（架构师裁决 b，叙事师字段 + 主编账本粒度合并）：
```sql
CREATE TABLE open_loops (
  id INTEGER PRIMARY KEY, novel_id INTEGER NOT NULL,
  title VARCHAR(200) NOT NULL,          -- 「百团大战赌局」
  parties TEXT DEFAULT '',              -- 陈屿、苏晚、国学社
  stake TEXT DEFAULT '',                -- 不清会失去什么
  origin_chapter INTEGER NOT NULL,
  opened_chapter INTEGER NOT NULL,      -- 首次成文提及章
  last_seen_chapter INTEGER,            -- 最近回响章
  expected_payoff_chapter INTEGER,      -- 可空=只挂账不排程
  status VARCHAR(20) DEFAULT 'open',    -- open→escalating→resolved / dropped
  settle_ratio REAL,                    -- 主编：本章兑付比例 0-1（0.8=爽点兑现80%）
  source VARCHAR(20) DEFAULT 'pending', -- pending/manual
  created_at VARCHAR(20));
```
2. ✅ **主编的兑付切片规则进事件清单 prompt**（红队也认的最小改动）：`_EVENT_SYSTEM` 加一句「至少一个微结局必须是未决/新增障碍（写实际状态变化，不留全清）」——这是 plan 层唯一改动。
3. ✅ **主编的章末反例词单做确定性观测**：「交接/结清/两清/账清了/尘埃落定/月底结清」命中章尾 300 字 → loop_audit 报告（advisory）。
4. ✅ **验收团队建议的 loop_audit Stage**（挂 Stage 3b，零 LLM）：未决事件计数趋势 + 章尾结清词 + 遗留逾期（expected_payoff <= n 未 resolved）三维，全 advisory 进 stages 与 Reflexion。
5. ✅ **注入端**：并入 build_plan_block（层 4 硬约束区），逾期/escalating ≤2 条 + 悬挂名单 ≤3 条，预算 ≤300 字符（架构师口径）。
6. ✅ **两段式信任**：LLM 的 openings/resolves 候选走 pending_extractions（kind="open_loop"），人工采纳才写真源；resolved 仅人工。
