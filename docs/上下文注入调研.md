## 1. "谁在本场"选择器

- **NovelCrafter Codex 四档**:Always include(常驻)/ Include when detected(名字+别名精确匹配才注入,默认)/ Don't include when detected / Never include(剧透永不进 AI)。检测范围=场景梗概/选中文本;有排除列表(角色叫 "Will" 时排除助动词 will);场景可手动绑定词条。
- **SillyTavern World Info**(按需注入最成熟实现):每条目 keys(支持正则);扫描最近 Scan Depth 条消息;三灯=🔵Constant 常驻/🟢Selective 关键词触发/Vectorized 向量召回;次级键 AND/NOT 条件注入;递归级联(条目内容提到其他条目的 key 时激活);预算耗尽即停,插入按优先级。中文要点:整词匹配开关建议关。
- **NovelAI Lorebook**:按**字符数**(最多 10,000 字符)而非消息条数扫描——更贴合小说流;每条目独立 token budget + insertion probability;级联+强制激活。
- **判定出场五种方式**:①大纲/场景文本提到名字(最可控)②最近 N 章/N 条消息出现过 ③向量召回 ④递归扩展 ⑤人工标记。实践主力=①+②,③兜底。
- **来源级保险**:`大纲卡写死出场名单`(entity_list)——判定发生在"计划层"而非"文本层",比事后扫描可靠(NovelForge 模式)。

## 2. Prompt 前缀缓存(核心杠杆)

| 厂商 | 机制 | 命中价 | 关键条件 |
|---|---|---|---|
| DeepSeek | 自动前缀缓存,默认开启 | **命中 ≈ 未命中的 1/30~1/50**(flash 档 $0.003 vs $0.15/M) | 前缀逐字节一致;TTL 数小时~数天 |
| OpenAI | 自动,≥1,024 token 起,128-token 块递增 | **半价** | 前 1024 token 一字之差全 miss;TTL 5-10 分钟(gpt-5 可 24h) |
| Anthropic | 显式 cache_control 断点,≤4 个 | **读 0.1x**(写 1.25x/5min TTL) | 分段命中;健康标准命中率 >85% 可省 70-90% |

**共同最佳实践**:"stable content at the beginning, dynamic content at the end, append-only"。
**禁止在缓存断点前放**:时间戳、每节点不同的标记、非确定序列化 JSON、顺序不定的内容。

## 3. 分层预算:按变化频率分,不按重要性分

上下文按变化频率切四层,每层成本不同:**forever-static(全站静态)/ per-story(篇级)/ per-node(节点级)/ per-attempt(每次重写)**。
位置比比例更重要:Lost in the Middle(U 型注意力)——关键信息放首尾;Anthropic 官方:长文档贴顶、**查询/指令放最末尾**(质量可提升 up to 30%)。系统提示只留 role+硬规则,动态参考数据放 user turn。封顶参照:Sudowrite Synopsis 封顶 4000 词;SillyTavern world info 按 Context% 预算。

## 4. 重写经济性

- **生成 vs 重写是两条预算路径**:Sudowrite 生成=全套 Story Bible+250 词前文;Rewrite=只作用选区(<600 词时只读 style 不读全量 bible),AI 自动选择性拉取 bible 元素。全量注入在重写场景确实是行业公认痛点(有专门 feature request)。
- **最小上下文重写模式**:只带原稿+意见(重写目标是"保持已定事实",上下文越多越容易整体重排);单问题单 prompt;负向约束("只修改直接涉及的段落")。
- **灵砚已有现成资产**:`review.py:_rewrite_by_nodes` 已经是 diff 式重写(评审意见 800 字+上一节点结尾 1500 字+原稿+节点大纲,不带全量设定)。
- **缓存视角**:同节点重写时前文/大纲/设定逐字未变——天生是前缀缓存最佳客户,不变部分(~90% token)全命中缓存价。

## 5. 常驻 vs 触发(三灯选择原则)

- **常驻赢**:主角/核心设定/文风锚例(召回失败不可接受;短篇常驻代价小,且白送缓存命中)。
- **触发赢**:配角/世界观条目/伏笔计划(数量多、单条不致命)。
- **召回兜底四层**:①精确名字匹配为主、向量为辅(混合检索 recall@10 65-78%→91%)②别名表+排除列表 ③CRAG 式降级(检索不足时扩大范围/降级常驻)④来源级保险(大纲卡写死名单)。
- 长篇、实体>50 个时检索式才有数量级优势;短篇常驻即可。

## 6. 对灵砚的三档方案

**现状问题**(`prompts.py:build_node_prompt`):persona+硬规则 → 完整大纲(**每节点变化的 ✓/★/○ 标记**)→ 约束/技巧/体裁 → **tone_inst(每次调用都变)** → 文风指纹+锚例;user 段=设定+前文 6000 字。动态块夹在静态块中间——**第一处字节差异即断缓存,当前命中率≈0**。

### 档 0:零改动纯排序(只改拼接顺序)——输入成本降 55-65%
四层重排:①全站静态(persona/规则/约束/技巧/体裁/文风指纹/锚例)→ ②篇级静态(角色/场景/主题/概念/完整大纲)→ ③节点级(当前节点卡)→ ④尾部动态(tone_inst/前文尾部/写作指令)。
**两个破坏性修正**:大纲行的 ✓/★/○ 动态标记改静态(或移到尾部层);"当前写哪个节点"信息移到尾部。
量化(10 节点×3 次≈30 调用×13k token):现状全 miss ≈ $0.059 → 档 0 ≈ $0.021-0.026,**降 55-65%**,且符合"指令放尾部"的注意力最佳实践。

### 档 1:选择器(在档 0 之上再降 10-15%,为蓝图铺路)
大纲 Agent 顺手产出 `entities: []`(出场角色,零额外调用);`build_node_prompt` 按名单过滤层 2;"上一节点出场角色默认延续"兜底 + 大纲卡名字匹配补漏。重写路径按评审意见维度只带对应约束子集。

### 档 2:触发式注入(SillyTavern 式)——拆书蓝图安全接入,成本 ~全量注入的 5-10%
蓝图实体建 world-info 结构 `{keys, mode: constant|trigger, budget, order, content}`;生成节点 i 时扫描**该节点大纲卡+上一节点结尾 1500 字**,命中 keys 才注入;主角/核心设定常驻(召回兜底底座)。注入条目按固定顺序(ID)拼接放层 2 后——同篇相邻节点命中集合高度重叠,缓存仍命中大半。
**结论:蓝图接入从成本问题变成排序问题**——全量常驻 8000 字×30 次也不到原成本 1.5 倍,触发式 <10%。

## 9. 生成期差异化与防雷同(2026-09-15)

调研结论与落地方案:见本文件 §4(差异化约束少而硬)与 [roadmap V3.8 生成期差异化节](roadmap.md)。
